The form is submitted via GET, so the complete search state lives in the URL: results stay bookmarkable and shareable, the back button works without a "resend form?" dialog, and the pagination links are able to reproduce the search at all. Deliberately NOT f:form: that ViewHelper always renders five __referrer[...] fields plus __trustedProperties, which with method="get" would end up in the query string of every result URL and would be dragged along by every link built from it. "action" and "controller" have to be hidden fields because a browser discards the query string of the action URL when submitting a GET form. The fragment is kept, so the anchor to the result headline survives (WCAG 2.4.3). role="search" turns the form into a search landmark, aria-label names it so that multiple landmarks on one page stay distinguishable (WCAG 1.3.1 / 2.4.1).
